# 高德当前导航 ETA 对照

## 目的

此增强在 CityScope 现有点到点路径结果旁提供高德当前驾车导航估计，用于观察静态道路模型与当前导航条件的差异。它不修改 `routing_edges.cost`，不参与 pgRouting 算路，也不改变 Isochrone 或应急响应。

## 架构

```text
WGS84 起终点
├─ CityScope：edge snapping → pgr_withPoints → 静态路线与 ETA
└─ FastAPI：高德坐标转换 → Driving API v2 → 当前 ETA / TMC
                                      ↓
                               仅作指标对照
```

接口为 `POST /api/v1/routing/traffic-comparison`，输入沿用现有 shortest-path 请求。FastAPI 先取得 CityScope 路线，再调用高德；响应保留完整 CityScope 路线，前端地图仍只绘制这条 WGS84 路线。

## 坐标体系与请求

- CityScope 输入及地图数据使用 WGS84 / EPSG:4326。
- 后端通过高德坐标转换 API 将起终点一次转换为 GCJ-02，并校验 `status`、`infocode` 及返回点数量。
- 转换失败时停止高德调用，不会将 WGS84 坐标直接冒充 GCJ-02。
- Driving API v2 使用 `strategy=32`、`show_fields=cost,tmcs`，始终采用高德返回的 `paths[0]`，并报告候选路线数量。
- 高德请求超时为 5 秒，不自动重试；Key 只从根目录 `.env` 读取。

## 返回字段

CityScope 与高德均返回距离、时长和由 `distance / duration × 3.6` 计算的平均速度。高德部分另含红绿灯数、收费金额、候选路线数和 TMC 构成。时长为 0 或缺失时不生成平均速度。

差异字段统一为：

```text
高德当前导航估计 − CityScope 静态道路模型
```

## TMC 语义

服务遍历 `paths[0].steps[].tmcs[]`，按 `tmc_status` 和 `tmc_distance` 汇总：畅通、缓行、拥堵、严重拥堵、未知。未识别状态进入 `unknown_m`。这些距离只用于当前路况构成展示，不推断速度，也不映射到 OSM edge。

## 降级策略

CityScope 路线先独立完成。Key 缺失、坐标转换失败、Driving API 错误、HTTP 错误、超时或响应字段异常时，高德部分返回：

```json
{
  "available": false,
  "reason": "安全且不含凭据的错误说明"
}
```

前端显示“当前导航对照暂不可用”，同时继续显示 CityScope 静态路线和指标。该行为已由 mock 测试和浏览器进程级无效 Key 场景验证。

## 限制

- CityScope ETA 仍使用静态道路等级速度，不代表实时交通。
- 高德结果是第三方当前导航估计，CityScope 不声称自行预测实时速度。
- 第一版不请求或绘制高德路线几何，不做 GCJ-02 逆转换。
- 不进行 TMC 到 OSM edge 的匹配，不生成动态 edge cost、动态 Isochrone 或动态应急响应。
- 高德服务可用性、配额和返回内容受第三方服务约束。
